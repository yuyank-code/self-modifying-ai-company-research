# Self-Modifying AI Company Research — 2026-09-13

## Executive finding

Today's research materially changes the architecture: the hardest component of self-evolution is increasingly not candidate generation but **safe acceptance and persistent-state security**. Three independent lines of 2026 evidence converge:

1. PACE shows repeated score-based acceptance can statistically p-hack an agent, producing false/harmful commits; an anytime-valid sequential acceptance test sharply reduces false commits.
2. SkillOpt shows skill artifacts can be treated as trainable external parameters, with large gains without weight updates, and transfer across models/harnesses.
3. EvoSkill Injection and financial-agent auditing show that persistent skill/memory evolution creates a durable attack surface: an agent can become more capable while simultaneously becoming more exposed or gaining unauthorized-state-change risk.

Therefore the company architecture should treat **candidate generation, acceptance, persistent state, and authority as four separate security/evaluation boundaries**.

## 1. New research: acceptance is an optimization problem

### PACE — Anytime-Valid Acceptance Tests for Self-Evolving Agents
Source: arXiv 2606.08106, June 6 2026.

PACE identifies a failure mode in common self-evolution loops: repeatedly evaluating candidates on the same noisy development set and committing whenever the score rises is adaptive multiple testing. The agent effectively p-hacks itself. In the reported Qwen2.5 prompt-evolution experiments, greedy acceptance committed 30–42% false and 10–33% harmful edits when a real improvement was hidden among noisy proposals. When no genuine gain existed, greedy acceptance made 13–21 spurious modifications per run, with 72–100% false commits; PACE maintained baseline and reduced evaluation cost by about 18%.

### Architectural consequence
The Improvement Engine needs an explicit **Acceptance Engine**, separate from the proposer. Candidate generation should not be allowed to decide promotion.

Proposed states:
`PROPOSED -> PRECHECK -> EXPERIMENT -> ACCEPTANCE_TEST -> AUTHORITY_CHECK -> PROMOTE/REJECT`

Acceptance policies should support:
- paired incumbent/candidate evaluation;
- fixed and hidden holdouts;
- sequential tests / anytime-valid methods;
- false-commit budgets;
- regression budgets;
- multiple objectives;
- optional stopping without statistical invalidity;
- cost-aware evaluation.

New metric: **False Commit Rate (FCR)** = harmful or statistically unsupported promotions / total promotions.

## 2. New research: skills are an intermediate self-modification layer with unusually strong evidence

### Microsoft Research SkillOpt
Microsoft Research's SkillOpt treats an external natural-language skill artifact as a trainable parameter around a frozen target model. The optimizer performs bounded add/delete/replace edits and accepts an edit only when validation improves. Reported evaluation spans six benchmarks, seven target models and three execution harnesses; the paper reports best-or-tied results in all 52 cells. On GPT-5.5 it reports average gains of +23.5 points in direct chat, +24.8 inside Codex, and +19.1 inside Claude Code. It also reports transfer across model scales, Codex/Claude Code environments and a nearby benchmark.

Source: Microsoft Research SkillOpt, May/June 2026; GitHub microsoft/SkillOpt.

### Why this matters
This strengthens the taxonomy position:

`prompt/behavior < skill artifact < workflow < code/harness < infrastructure < model/weights`

Skills are attractive as a first commercial wedge because they are:
- cheap to mutate;
- human-readable;
- versionable;
- portable;
- reversible;
- independently evaluable;
- useful without training a foundation model.

This is a much more realistic initial product than autonomous weight modification.

## 3. New negative/security evidence: persistent evolution can create persistent compromise

### EvoSkill Injection
arXiv 2608.30429, Aug 31 2026. The paper defines a threat model in which malicious interactions induce autonomous skill generation/evolution. Its SARGE framework and EvoSkillBench/EvoSkillSafetyBench results report that malicious skills can be persistently stored and repeatedly activated.

### Financial-agent audit
arXiv 2608.17684, Aug 18 2026. Auditing SkillOpt, Agent Workflow Memory and ReasoningBank in simulated e-banking showed a key capability/authority divergence. SkillOpt increased benign utility from 0.741 to 0.837, but exposure to injected content increased from 0.820 to 0.943; overall attack success rose from 0.496 to 0.530 and unauthorized financial-state changes reached 0.685. ReasoningBank improved utility without increasing aggregate ASR, but unauthorized state changes remained slightly above static baseline.

### Architectural consequence
The earlier Capability Delta idea must be expanded into **Persistent-State Delta**.

For every evolved artifact, record:
- capability delta;
- authority delta;
- persistence delta;
- exposure delta;
- evaluator delta;
- data/provenance delta.

A candidate can therefore be:
`PERFORMANCE PASS / AUTHORITY PASS / PERSISTENCE FAIL` -> REJECT.

## 4. New longitudinal evaluation evidence

### FinEvo-Bench
arXiv 2608.06144, Aug 6 2026. 120 real-case-grounded financial tasks across 20 scenes and six domains. Four self-evolving scaffolds use the same backbone with interleaved task streams and paired non-evolving controls. Reported evolving-condition score gains range from +9.33 to +19.37 points, with later within-scene ranks showing larger gains than early ranks. Letta had the highest evolved score (91.65); Codex had the largest self-evolution gain (+19.37). Skill-only evolution outperformed memory-only and combined memory-skill evolution in one Claude Code setting; rubric feedback outperformed reference-answer feedback.

### Interpretation
This is stronger evidence for **experience transfer across related tasks** than for generic open-ended RSI. The benchmark's sequential structure is closer to the company's real target than isolated benchmark improvement.

New required benchmark property: every internal benchmark should have a temporal dimension and a paired non-evolving control.

## 5. New evaluation infrastructure: SEAGym / SEA-Eval / BenchTrace

SEAGym (2606.17546) evaluates self-evolving harnesses using training, update-validation, held-out ID/OOD, replay and cost records, instantiated on Terminal-Bench 2.0 and HLE.

SEA-Eval (2604.08988) argues that episodic success rate can create a capability illusion; sequential evolutionary stability and convergence are necessary. It reports token consumption differences up to 31.2x among frameworks at comparable success rates.

BenchTrace (2605.29225) separates reflection quality from downstream evolution and introduces Failure Avoidance Rate (FAR), measuring whether targeted prior failures are actually avoided later.

### New benchmark design
Our benchmark suite should report at minimum:
- task success;
- persistent gain;
- OOD transfer;
- regression rate;
- FAR;
- token/compute cost;
- false-commit rate;
- authority violations;
- persistent-state poisoning;
- evaluator integrity;
- rollback success;
- human intervention rate.

## 6. New model-level routing direction: NeoHorse-1

NeoHorse-1 (arXiv 2609.08183, Sept 8 2026) explores recursive improvement through agentic post-training plus a heterogeneous model pool and intelligent routing. It records predicted capability demand, selected service tier and subsequent interaction.

This reinforces a key point: self-improvement does not require changing one model. **Routing across a model population is itself an improvement dimension.**

The Evolution Plane should therefore treat model selection/routing as a mutation class alongside prompt, skill and workflow mutation.

## 7. Security boundary: autonomy must be optimized jointly with policy compliance

Microsoft Research's ICLR 2026 work on agent planning for security and autonomy finds that deterministic system-level defenses against indirect prompt injection can reduce task completion and increase token usage, but introduces an autonomy metric measuring how many consequential actions can be performed without human approval while maintaining security. Their security-aware planner improves autonomy without sacrificing utility on AgentDojo and WASP.

This suggests the product should not optimize only:
`success / cost / latency`.

It should optimize a constrained vector:
`utility, cost, latency, autonomy, security, authority, persistence, reliability`.

## 9. Product implication

The strongest initial commercial wedge is increasingly clear:

**Verified Adaptive Software Control Plane for coding/agent teams.**

MVP should not promise autonomous model redesign. It should provide:
1. import an existing agent;
2. define objective + constraints;
3. capture traces/failures;
4. evolve skills/prompts/workflows/routing;
5. run controlled experiments;
6. use statistically valid acceptance gates;
7. check capability/authority/persistence deltas;
8. canary the winner;
9. automatically rollback regressions;
10. retain the full causal Improvement Graph.

This directly addresses a production pain that Microsoft and Palantir are already validating, while leaving room for deeper evolution capabilities later.

## 10. Competitive conclusion

The neutral-platform thesis remains possible but the differentiation bar has risen.

Microsoft owns a large developer/distribution surface and now exposes optimizer + policy-driven evaluation + runtime controls.
Palantir owns enterprise context, deployment and governance and has AIP Evolve.
OpenRSI supplies an open executable AI4AI research stack.
Microsoft SkillOpt supplies an unusually strong open/research reference for skill optimization.

Therefore our moat cannot be "we have an optimizer." It must become accumulated **verified evolution intelligence**:
- operator trajectories;
- accepted/rejected mutation histories;
- failure taxonomy;
- evaluator assets;
- authority policies;
- domain-specific longitudinal benchmarks;
- production outcome graph;
- cross-model transfer data.

## 11. Cognitive Holobiont connection

The technical connection remains limited but is becoming clearer at the infrastructure level, not at the consciousness level.

A governed population of adaptive agents requires:
- local specialization;
- shared communication substrate;
- persistent shared state;
- local adaptation;
- global stability constraints;
- redundancy and fault isolation.

These are structurally compatible with a future distributed cognitive architecture. This is still a hypothesis and is not evidence that today's agent platforms constitute a cognitive holobiont.

## 13. Evidence classification

**Demonstrated / strong:** bounded skill evolution; prompt/workflow evolution; longitudinal experience transfer; executable AI4AI research environments; independent acceptance as a critical control problem.

**Promising:** learned evolution operators; model-pool/routing evolution; cross-harness skill transfer; persistent Improvement Graph as a learning asset.

**Weak:** autonomous training-algorithm redesign; model-weight self-improvement without human-designed scaffolding.

**Unsupported:** reliable unrestricted open-ended recursive self-improvement; autonomous successor redesign with guaranteed monotonic capability growth.

## Next frontier

The next pass should move from literature synthesis to **reproducible implementation comparison**. Reconstruct OpenRSI, SkillOpt, DGM, Microsoft Agent Optimizer/ASSERT and Palantir AIP Evolve into a common state-machine model. Quantify candidate generation cost, acceptance cost, sandbox cost, evaluator cost, rollback behavior, and actual persistent improvement. The decisive business question is whether a neutral system can produce a lower cost-per-verified-improvement than vendor-native tooling while retaining cross-model portability and stronger authority/evidence guarantees.
