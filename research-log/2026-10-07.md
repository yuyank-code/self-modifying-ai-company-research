# Deep Research Log — 2026-10-07

## Executive conclusion

The program now has a sharper Evidence Contract requirement: an EvolutionCommit must bind the exact model, harness, evaluator, benchmark/task set, runtime, tools, authority policy and configuration that produced its evidence. Evidence must be automatically classified as VALID, CONDITIONAL, STALE, INCOMPATIBLE or UNVERIFIABLE when any component changes.

## Changed conclusions

1. Evidence validity is a product primitive, not documentation.
2. The scaffold is part of the system under test.
3. Reliability and cost must be co-optimized; pass@1 alone is insufficient for production promotion.
4. Runtime security is increasingly an integration layer; the differentiated layer should be evolution scope, evidence, provenance, acceptance and deployment.
5. Bounded harness evolution remains the strongest near-term RSI substrate; weight-level/open-ended successor redesign remains unsupported.
6. The commercial wedge remains adaptive-software change control.

## Evidence Contract v0.1

Every EvolutionCommit should bind parent/candidate digests, model and harness versions, tool/MCP versions, runtime/security substrate, evaluator versions, benchmark/task-set digest, reference trajectories, authority policy, budgets, seeds, cost/latency, security results, statistical acceptance, deployment result and rollback pointer.

Evidence status: VALID / CONDITIONAL / STALE / INCOMPATIBLE / UNVERIFIABLE.

## Economic metric

Verified Improvement Yield (VIY) = verified production value delta / total evolution cost, including generation, search, evaluation, hidden verification, security, replay, deployment and rollback.

Reliable Improvement Rate (RIR) = accepted candidates that improve pass^N on held-out tasks / accepted candidates.

## Moat update

The strongest moat candidate is the combination of portable Evolution/Evidence contracts, historical failure/repair lineage, cross-harness/model/runtime transfer data, evaluator/security adapters and production-outcome feedback.
