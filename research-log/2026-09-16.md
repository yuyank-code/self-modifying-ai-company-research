# Self-Modifying AI Company Research — 2026-09-16

## Executive finding

Today's pass shifts the core technical question from **whether an agent can improve** to **whether the platform can learn when to improve, what knowledge to retain, and which changes are worth their evaluation cost**.

Four fresh lines of evidence matter:
1. RSIAgent demonstrates training-free recursive exploration through frozen environment-specific causal memory.
2. Prime Agent provides a large-scale open-source self-improving coding/RLM harness, making the harness itself a practical research object.
3. MEGA formalizes durable operational knowledge as a self-evolving graph rather than raw memory.
4. Microsoft RHO shows a path toward self-supervised harness optimization when labeled validation data is scarce.

Together they suggest a potentially valuable platform primitive: **an Improvement Intelligence Layer that learns the economics and reliability of improvement operators from accumulated trajectories.**

## 1. RSIAgent: recursive exploration can improve without weight updates

RSIAgent (arXiv:2609.15364, submitted September 14, 2026) uses curriculum, actor, and verifier agents to explore unfamiliar environments. It explicitly separates broad exploration from deep exploration and stores reusable causal relationships between actions, conditions, and consequences in frozen memory. The reported experiments cover OSWorld-v2 and Agent's Last Exam and claim substantial gains for open-source models.

Source: https://arxiv.org/abs/2609.15364

### Why this is new for the program

This is stronger evidence for **environment-specific knowledge acquisition without parameter training**. The unit of adaptation is not merely a summary or prompt; it is a causal memory representation.

### Architectural implication

Our State Plane should distinguish:
- episodic trace;
- semantic skill;
- causal environment model;
- procedural skill;
- evaluator evidence;
- negative/failure knowledge.

A generic vector-memory layer is therefore probably insufficient for high-reliability evolution.

## 2. Prime Agent: self-improving coding harnesses are becoming mainstream open-source artifacts

Prime Agent is an open-source self-improving RLM harness for coding workflows and long-running autonomous tasks. The repository reports more than 20k GitHub stars and exposes a persistent harness rather than a one-shot agent script.

Source: https://github.com/PrimeIntellect-ai/prime-agent

### Company implication

The generic self-improving coding-agent harness is rapidly commoditizing. A startup should not compete on merely shipping another recursive coding loop.

The defensible layer is increasingly above the harness:
- independent evaluation;
- policy enforcement;
- cross-harness compatibility;
- improvement economics;
- provenance;
- production rollback;
- cross-model portability;
- historical improvement intelligence.

## 3. MEGA: operational knowledge can become an optimization substrate

MEGA (arXiv:2608.10504) proposes a self-evolving infrastructure called Meta Evaluation-Grounded Adaptation. It distills agent sessions into durable wisdom, decomposes that wisdom into typed PCR units in a Wisdom Graph, performs compositional retrieval, and feeds operational evidence back into both the knowledge and optimization process.

Source: https://arxiv.org/abs/2608.10504

### New hypothesis

The Improvement Graph previously proposed in this research may need to become more than causal provenance. It may need two linked layers:

**Evidence Graph:** what happened and what changed.

**Knowledge Graph:** what reusable strategy was learned from those outcomes.

The distinction matters because provenance answers **"what happened?"** while optimization intelligence answers **"what should we try next?"**

## 4. Microsoft RHO: self-supervised harness optimization is commercially important

Retrospective Harness Optimization (RHO), Microsoft Research, June 2026, optimizes an agent harness using past trajectories rather than requiring a labeled validation set. It selects a diverse coreset of difficult historical tasks, re-solves them, generates candidate harness updates and selects through self-preference. The paper reports a single-round SWE-Bench Pro pass-rate increase from 59% to 78% without external grading.

Source: https://www.microsoft.com/en-us/research/publication/retrospective-harness-optimization-improving-llm-agents-via-self-preference-over-trajectory-rollouts/

### Important caveat

Self-preference is not equivalent to independent verification. RHO is valuable evidence for reducing the labeled-data bottleneck, but it cannot replace an independent acceptance layer when the system is allowed to optimize against its own judgment.

This creates a two-stage architecture:

**cheap self-supervised search → expensive independent acceptance.**

That may materially improve platform economics.

## 5. SkillOpt strengthens the text-space parameter thesis

SkillOpt treats external agent skills as trainable parameters around a frozen model. It reports best/tied-best results across 52 model/benchmark/harness cells and transfer across models and execution environments.

Source: https://www.microsoft.com/en-us/research/publication/skillopt-executive-strategy-for-self-evolving-agent-skills/

### Updated taxonomy

The most commercially accessible mutable parameter layers currently appear to be:

1. prompt;
2. skill;
3. memory/causal knowledge;
4. routing;
5. workflow;
6. harness code;
7. tool ecosystem;
8. infrastructure/configuration;
9. model components;
10. weights;
11. successor architecture.

The first seven are increasingly plausible as a product today. The last four remain research-heavy or capital-intensive.

## 6. Self-evolution should optimize *improvement efficiency*, not just task performance

A platform can spend enormous inference/evaluation compute discovering a tiny improvement. Therefore today's research introduces a new primary economic metric:

### Verified Improvement ROI (VI-ROI)

VI-ROI = (economic value of verified production improvement) / (all incremental improvement costs)

Costs should include:
- candidate-generation tokens;
- evaluator tokens;
- GPU/CPU execution;
- sandbox overhead;
- storage;
- human review;
- failed candidates;
- canary cost;
- rollback cost;
- security analysis.

Value can include:
- engineer-hours avoided;
- inference cost saved;
- latency reduction;
- reliability improvement;
- revenue increase;
- incident reduction.

This is the metric that can connect research to a real business.

## 7. New architecture: Improvement Intelligence Layer

The platform architecture is now:

**Evolution Plane** — operators, candidate generation, search.

**Evidence Plane** — evaluators, hidden tests, acceptance statistics.

**State Plane** — episodic traces, skills, causal knowledge, Improvement Graph.

**Harness Plane** — tools, MCP, specialist agents, routing, environment versions.

**Authority Plane** — identity, permissions, credentials, sandbox, action boundaries.

**Deployment Plane** — promotion, canary, monitoring, rollback.

### New layer

**Improvement Intelligence Layer**
- operator success priors;
- failure taxonomy;
- task/operator matching;
- cost models;
- transfer estimates;
- regression predictions;
- expected improvement per compute;
- experiment allocation;
- historical trajectory retrieval.

This layer chooses **where to spend improvement compute**.

## 8. New product primitive: Improvement Budget Allocation

Instead of giving an evolution loop an arbitrary fixed number of iterations, the platform should allocate budget based on expected value.

For each candidate operator/task pair:

`Expected Gain × Probability of Acceptance × Transfer Probability / Expected Cost`

Candidates with low expected value should be stopped early.

Candidates with high expected value receive additional search/evaluation budget.

This is analogous to portfolio allocation or bandit optimization, but applied to engineering changes.

## 9. Security update: adaptive systems need provenance for learned knowledge

RSIAgent's causal memory, SkillOpt's skill artifacts, RHO's harness changes and MCP tools all create persistent objects that can affect future behavior.

Therefore every persistent adaptive artifact should carry:
- creator/model identity;
- source trajectories;
- evaluator evidence;
- applicable environment/harness versions;
- authority implications;
- dependencies;
- cryptographic/content hash;
- expiration/revalidation policy;
- revocation status.

This makes **Adaptive Artifact Provenance** a cross-cutting security primitive.

## 10. Current safety environment reinforces the product opportunity

OpenAI's September 2026 alignment statement emphasizes that increasingly capable systems face generalization problems and argues for stronger monitoring, safety cases, and third-party evaluation as automated AI research progresses.

Source: https://openai.com/index/an-alien-mind/

Anthropic CEO Dario Amodei has separately called for third-party evaluators to receive substantial access to frontier systems and for stronger shared safety bars.

Source: https://darioamodei.com/post/we-must-pace-the-frontier

These are policy/strategy signals rather than proof of RSI, but they strengthen the commercial relevance of auditable evaluation and control infrastructure.

## 11. Competition update

Palantir AIP Evolve remains a direct commercial benchmark: it coordinates AI FDE fleets around target objectives, validation strategies and operational constraints.

Source: https://www.palantir.com/docs/docs/foundry/announcements

Microsoft simultaneously has SkillOpt, RHO, EvoTest and Agent Optimizer research/product directions.

The implication is that **vendor-native optimization will be increasingly common**.

Our neutral-platform thesis therefore requires a measurable advantage in at least one of:
- model/provider neutrality;
- enterprise data isolation;
- independent verification;
- cross-agent portability;
- long-term improvement-history learning;
- security/provenance;
- production migration and rollback;
- lower verified-improvement cost.

## 12. New contradiction

More sophisticated adaptation is not automatically more valuable.

- RHO reduces dependence on labeled validation but relies on self-preference.
- RSIAgent constructs richer causal memory but still depends on verifier quality.
- SkillOpt optimizes external state but needs held-out validation.
- MEGA argues for compositional knowledge but adds graph/reasoning complexity.

Therefore there is a likely **complexity frontier**: after some point, additional adaptive machinery can cost more than the improvement it creates.

This must be measured rather than assumed.

## 13. New experiments E49–E56

**E49 — causal-memory vs vector-memory:** compare downstream adaptation using raw traces, summaries, embeddings, skills, and causal action-condition-consequence memory.

**E50 — self-supervised search + independent acceptance:** compare RHO-style search with and without protected external evaluation.

**E51 — improvement-budget bandit:** fixed iteration budget versus expected-value allocation.

**E52 — operator priors:** cold-start operator selection versus history-trained operator selection.

**E53 — graph retrieval ablation:** embedding-only vs graph-only vs hybrid Improvement/Evidence Graph retrieval.

**E54 — adaptive-artifact provenance:** measure attack and regression rates with/without signed/versioned persistent artifacts.

**E55 — complexity frontier:** progressively add memory, skills, routing, critics, graphs and operators while holding task budget constant; find where marginal verified gain becomes negative.

**E56 — VI-ROI:** calculate economic value per verified improvement on a controlled coding workflow.

## 14. Company formation implication

The first product should now be designed around a customer's existing agent rather than requiring them to adopt a new agent.

**Input:** OpenAI/Anthropic/open-source coding or workflow agent.

**Platform:** observe → propose → search → verify → migrate → canary → learn.

**Output:** lower cost, higher reliability, better latency, or improved task success with an auditable evidence package.

This reduces distribution friction and protects against the risk that the company's own foundation model becomes obsolete.

## 15. Long-term Cognitive Holobiont connection

The strongest justified connection today is not consciousness. It is **distributed adaptive specialization**:

- causal memories = local experience;
- skills = specialized capabilities;
- agents = specialized components;
- shared graphs = collective memory;
- verifiers = homeostatic constraints;
- authority layer = boundary regulation;
- evolution layer = adaptation;
- deployment/rollback = stability mechanism.

This is a systems analogy, not evidence that such infrastructure produces a biological or conscious holobiont.

## 16. Evidence boundary

**Demonstrated/strong:** bounded skill/context evolution; executable coding-agent evolution; training-free environment adaptation; persistent operational knowledge; harness optimization; need for external verification.

**Promising:** causal-memory representations; improvement-intelligence layer; learned operator selection; adaptive artifact provenance; budget-aware evolution.

**Weak/unresolved:** autonomous model-weight evolution; autonomous training-algorithm redesign; economically superior open-ended RSI.

**Unsupported:** guaranteed monotonic RSI, unrestricted successor redesign, or current agent ecosystems being a Cognitive Holobiont.

## 17. Exact continuation point

The next pass should build the **Common Evolution State Machine v1**.

For each major implementation, reconstruct a normalized record:

`System -> Model -> Mutable State -> Operator -> Candidate -> Environment -> Evaluator -> Acceptance -> Archive -> Authority Delta -> Deployment -> Outcome -> Cost`

Systems to normalize:
- OpenRSI/OpenMLE;
- Darwin Gödel Machine;
- Prime Agent;
- SkillOpt;
- RHO;
- EvoTest;
- RSIAgent;
- Palantir AIP Evolve;
- Microsoft Agent Optimizer.

The next decisive research question is whether these systems can be represented by one portable protocol without losing their differentiating capabilities. If yes, that protocol becomes a candidate foundation for the company's SDK/API and future ecosystem.
