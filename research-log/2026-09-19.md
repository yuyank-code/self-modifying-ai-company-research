# Self-Modifying AI Company Research — 2026-09-19

## Executive finding

Today's pass materially changes the proposed platform protocol. The strongest new evidence is **ModularRSI**, which demonstrates that benchmark-disjoint, modular harness evolution can transfer across unseen tasks and even across foundation models, while joint/monolithic evolution can perform worse than the baseline. In parallel, **TRACE** has emerged as an open, vendor-neutral specification for portable, signed runtime evidence for AI-agent executions. Together these imply that a commercially credible adaptive-AI platform should not treat the evolving agent as one mutable object. It should expose **typed evolution scopes** and produce **portable, independently verifiable execution/evolution evidence**.

## 1. ModularRSI: modularity is not an implementation detail; it is an optimization constraint

ModularRSI (arXiv:2609.14857, 14 Sep 2026) argues that whole-harness evolution entangles unrelated mechanisms and makes attribution difficult. It decomposes the harness into five modules: Agent Loop, Tool Use, Observation Management, Context Management, and Task Completion Detection. It uses benchmark-disjoint evolution data and contrasts successful and failed trajectories across tasks to identify recurring deficiencies. Source: https://arxiv.org/abs/2609.14857. Source quality: primary preprint. Confidence: medium-high for reported experimental results; independent replication remains absent.

Reported primary experiment with DeepSeek-V4-Flash-Preview:
- TerminalBench 2.0: 47.57% baseline -> 52.43% evolved.
- SWE-Bench Verified: 73.40% baseline -> 76.45% evolved.
- Terminal-domain evolution transfers to SWE-Bench: 75.80%.
- Software-engineering evolution transfers to TerminalBench: 49.40%.
- Pass^3 on TerminalBench improves 30.34% -> 35.96% for the in-domain evolved harness.
- Non-modular evolution reaches 46.44% and joint evolution of all modules 44.19%, both below the 47.57% baseline.
- Agent Loop evolution gives the largest single-module gain to 50.56%.
- Observation Management reduces average interaction steps from 34.70 to 22.50.
- Cross-model transfer is reported for GLM-5.2, MiniMax-2.5 and DeepSeek variants.

Strategic interpretation: **more mutation scope is not necessarily more intelligence**. Mutation scope should be a typed resource. This supports Evolution Schemas with explicit allowed modules, maximum diff surface, dependency rules and evaluation requirements.

## 2. New protocol concept: Evolution Scope Contract

Define an Evolution Scope Contract with:
- mutable modules;
- immutable modules;
- allowed operator classes;
- dependency graph;
- maximum semantic diff;
- required evaluator families;
- required hidden/holdout tests;
- authority ceiling;
- persistence/state-change ceiling;
- rollback requirements;
- provenance requirements.

A candidate that exceeds scope is rejected before expensive evaluation.

This is analogous to a typed API boundary: the system does not merely ask whether a change is good; it asks whether the change is **legal to consider**.

## 3. TRACE is a major development for the Evidence/Authority planes

TRACE (Trust, Runtime Attestation, and Compliance Evidence) is now hosted as a Linux Foundation project. The specification defines portable signed evidence describing what model/code/runtime executed, under which policy, on what data class, invoking which tools. It composes RATS/EAT, SLSA, SCITT, SPIFFE and EAR and maps the execution surface to MCP/A2A. The reference build targets confidential MCP and hardware attestation across Intel TDX, AMD SEV-SNP and NVIDIA confidential GPUs. Sources: https://trace.agentrust-io.com/spec/trace-v0.1/ and https://github.com/agentrust-io/trace-spec. Source quality: primary specification/repository plus Linux Foundation reporting. Confidence: high for current specification status; production maturity remains limited because the repository itself labels v0.2 a developer preview.

The Linux Foundation reports nearly 135,000 PyPI downloads in the first 10 weeks after introduction and says TRACE is intended to provide portable, independently verifiable runtime evidence across clouds and infrastructure. Source: https://www.linuxfoundation.org/blog/linux-foundation-newsletter-september-2026. This is adoption signal, not proof of enterprise product-market fit.

Critical implication: our platform's Evidence Plane should not invent a proprietary evidence format if open standards can carry the basic execution proof. We should consider **Evolution Commit as an extension layer above portable runtime evidence**, not as a replacement for it.

## 4. Common Evolution State Machine v1

Today's normalization of the research yields the following candidate state machine:

`Agent/Model Artifact`
-> `Harness + State Snapshot`
-> `Evolution Scope Contract`
-> `Operator`
-> `Candidate Artifact`
-> `Sandbox Execution`
-> `Evidence Record`
-> `Independent Evaluation`
-> `Performance/Capability/Authority/Persistence Deltas`
-> `Acceptance Decision`
-> `Evolution Commit`
-> `Archive/Lineage`
-> `Canary`
-> `Production Outcome`
-> `Replay Dataset`
-> `Improvement Intelligence`
-> next `Operator/Budget` selection.

This state machine can represent prompt, memory, skill, routing, workflow, code, harness, infrastructure and eventually model-component evolution while keeping their risk classes separate.

## 5. New distinction: Evolution Scope vs Evolution Depth

Evolution depth measures how deep in the stack the mutation reaches:
Prompt < Skill < Memory < Routing < Workflow < Code < Harness < Infrastructure < Model component < Weights < Successor redesign.

Evolution scope measures how much of a layer is allowed to change.

A deep mutation with tiny scope may be safer and more generalizable than a shallow mutation with huge scope. Therefore the platform should optimize in a 2D space rather than assuming deeper evolution is better.

## 6. Dream-RSI: replay is now a core economic primitive

Dream-RSI (arXiv:2609.14858, 14 Sep 2026) proposes turning historical discovery trees into replay simulators so exploration policies can be improved offline without repeatedly invoking expensive online discovery. It reports competitive or improved discovery quality with substantially reduced discovery cost across algorithm engineering, mathematical optimization and GPU-kernel engineering. Source: https://arxiv.org/abs/2609.14858. Source quality: primary preprint. Confidence: medium; generalized economic claims require independent reproduction.

The architecture should therefore separate:
- Search compute: candidate generation/exploration.
- Replay compute: cheap offline policy improvement.
- Trust compute: protected evaluation/security/acceptance.

The research program's central economic objective becomes **Verified Improvement Cost (VIC)** rather than raw benchmark gain.

## 7. Independent evaluation is becoming an industry-scale market

Anthropic and Accenture announced a commitment of at least $2B over five years toward independent frontier-model evaluation, with embedded evaluators and red-teaming. Reuters reports the partnership on 18 Sep 2026. Source: https://www.reuters.com/business/anthropic-accenture-invest-2-billion-ai-model-evaluation-safety-concerns-rise-2026-09-18/. Source quality: Reuters reporting on announced partnership. Confidence: high for reported announcement; detailed operating economics remain unknown.

This is strategically important: independent evaluation is no longer merely an academic safety subproblem. It is becoming a budgeted infrastructure function.

Our company should therefore distinguish:
- customer-owned evaluator;
- vendor evaluator;
- independent evaluator;
- regulator/auditor evidence export.

## 8. OpenAI's new misalignment-reporting framework creates a useful operational model

OpenAI introduced a framework on 16 Sep 2026 to track, investigate and disclose unexpected or concerning model behavior, including publishing incidents before investigation/mitigation is fully complete when appropriate. Source: https://openai.com/index/model-misalignment-reporting-framework/. Source quality: primary company disclosure. Confidence: high.

This suggests that our platform should have an **Evolution Incident Record** linked to Evolution Commits. A production regression, unauthorized action, evaluator anomaly or provenance failure should be traceable to the exact candidate lineage and promotion evidence.

## 9. Security baseline is rising with model capability

OpenAI's GPT-6 Astra safety overview states that Astra meets its Critical cybersecurity capability threshold and describes stricter isolation, checkpoint encryption, full-trajectory monitoring and blocking alignment evaluation before internal use. Source: https://openai.com/index/safety-overview-gpt-6-astra/. Source quality: primary. Confidence: high for disclosed controls.

Strategic implication: the Authority Plane must include infrastructure-level controls rather than relying on prompt policy. High-capability agents need stronger isolation as a direct function of capability.

## 11. New competitive thesis

The neutral platform's defensibility is now less likely to be a proprietary agent runtime and more likely to be a **vendor-neutral evolution/evidence layer** that sits above runtimes.

Potential stack:
1. Open agent protocols (MCP/A2A/etc.)
2. Agent runtime/harness
3. Evolution Scope Contract
4. Improvement Engine
5. Portable Evidence/Attestation (TRACE-compatible)
6. Independent Evaluation
7. Evolution Commit/Lineage
8. Production Governance
9. Improvement Intelligence
10. Marketplace/Operator Registry.

This architecture minimizes the amount of foundational infrastructure the startup must own while maximizing the proprietary value in verified improvement history, operators, evaluators and production outcomes.

## 12. New negative result / contradiction

ModularRSI's finding that joint evolution of all modules underperformed the baseline is a direct warning against building an enormous universal optimizer first. Complexity and mutation breadth can make attribution and validation worse. This contradicts the intuition that a more powerful optimizer with a larger search space should always dominate smaller specialized optimizers.

Decision: **start with constrained, modular evolution and add cross-module optimization only after proving module-level value.**

## 13. New experiments E75-E84

**E75 — Scope-size curve:** vary maximum mutable module set and measure verified improvement per compute.

**E76 — Modular vs monolithic evolution:** reproduce ModularRSI under a common evaluation protocol.

**E77 — Cross-model harness portability:** evolve on one model and evaluate on at least three others.

**E78 — Evolution Scope Contract enforcement:** adversarially attempt out-of-scope mutations; measure prevention rate and false blocks.

**E79 — TRACE-compatible Evolution Commit:** attach evolution metadata to portable runtime evidence and verify independently.

**E80 — Evidence tampering test:** mutate logs/evaluator results/artifacts and test whether the lineage remains invalidated.

**E81 — Replay amortization:** measure break-even number of future improvement attempts where replay becomes cheaper than fresh search.

**E82 — Independent evaluator marketplace:** compare vendor, customer, and third-party evaluators on correlated failure and cost.

**E83 — Evolution incident reconstruction:** inject a production regression and reconstruct its causal lineage automatically.

**E84 — Minimal protocol prototype:** implement the Common Evolution State Machine as a small local service before building a full platform.

**P-17:** Portable runtime evidence can become a foundational trust primitive for adaptive software.

**P-18:** Evolution Commit can be an interoperable metadata layer above runtime evidence rather than a closed proprietary format.

## 15. Business implications

Initial product should likely avoid claiming general RSI. A realistic first offering is:

**Adaptive Agent CI/CD + Evidence Gateway**

It ingests an existing agent/harness, permits only declared mutation scopes, runs candidate changes in sandbox, attaches portable execution evidence, invokes protected evaluators, creates Evolution Commits, and gates production deployment.

Likely initial buyers:
- AI platform engineering teams;
- enterprise agent teams;
- coding-agent teams;
- security-conscious AI deployments;
- regulated organizations needing evidence.

Pricing hypothesis remains usage/compute plus enterprise platform fee, but the value metric should eventually be **verified improvements and governed agent executions**, not token volume alone.

## 16. CUDA analogy update

The ecosystem prerequisite is becoming clearer. CUDA had a stable programming model and portable tooling over changing hardware. Adaptive software would need a stable **Evolution Contract** and **Evidence Contract** over changing models/harnesses.

A plausible ecosystem flywheel is:

`standard evolution API -> third-party operators/evaluators -> portable evidence -> more integrations -> more verified improvement trajectories -> better operator selection -> lower VIC -> more adoption`.

This is still a hypothesis. The key falsification experiment is whether third-party operators and evaluators actually produce useful interoperability without the platform becoming a thin wrapper.

## 17. Cognitive Holobiont connection

Today's result makes the long-term analogy more technically grounded: modular adaptive components, typed interfaces, shared evidence/state, local adaptation and global homeostatic constraints resemble a distributed adaptive computational architecture. The platform should therefore prioritize interoperability, modular specialization and shared-but-governed state.

Still speculative: this is not evidence for biological equivalence, consciousness, or literal holobiont realization.

## 18. Updated evidence boundary

**Demonstrated:** modular harness evolution with benchmark-disjoint transfer (paper-level evidence); longitudinal self-evolution; replay-based exploration as a research mechanism; external authority/evidence requirements; portable runtime evidence standards emerging.

**Promising:** cross-model harness transfer; Evolution Scope Contracts; TRACE-compatible Evolution Commits; replay economics; independent-evaluator infrastructure.

**Weak/unresolved:** autonomous training-algorithm redesign; model-weight RSI; open-ended successor redesign; economic superiority of unrestricted autonomous evolution.

**Unsupported:** guaranteed monotonic RSI or a present-day Cognitive Holobiont.
